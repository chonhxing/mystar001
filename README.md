## 1. 先说清楚：小游戏和小程序是两个运行时

你最早说"微信小程序的小游戏"，后来给了小游戏的开发文档。这两个在微信里是**完全不同的东西**，
所以我把它做成了两个工程，共享同一套算法、数据、后端：

|  | 小游戏（**根目录**，主目标） | 小程序（`miniprogram/`，备用） |
| --- | --- | --- |
| 界面 | **Canvas 自绘**，没有 WXML/WXSS，UI 全得自己写 | WXML + WXSS，写起来快、文字排版好 |
| 入口 | `game.js` + `game.json` | `app.js` + `app.json` + pages |
| 类目 | **只能选"游戏"，且不可更改**（官方明文） | 可选其他类目（审核卡住时的后手） |
| 变现 | 激励视频/插屏广告、游戏中心分发 | 流量主广告（门槛更高） |
| 状态 | ✅ 玩法框架完成，7 个场景 | ✅ 完成且测试通过，作为参考实现 + 后备 |

**为什么两个都留**：小游戏账号一旦建成就是"游戏"类目，不可逆；而内容合规上有明文风险
（详见 COMPLIANCE）。留一个小程序版，成本只是改完共享代码跑一次 `npm run sync`。

## 2. 跑起来

### 小游戏（主目标）
1. 装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)
2. **导入项目 → 选择这个仓库的根目录**（`project.config.json` 的 `compileType` 已经是 `game`）
3. 没有 AppID 就先点「测试号」
4. 编译即可玩。此时 `config.USE_REMOTE` 默认是 `true` 但后端没起，**会自动降级成本机解读**，
   流程照走不误（结果页会显示一句"星象信号不好，这次用本机图谱为你解读"）

### AI 解读连不上？按这个查

**先看「我的 → 设置 → 解读服务状态」**，它会直接告诉你原因和该怎么办。

| 显示 | 原因 | 怎么修 |
| --- | --- | --- |
| `域名未校验` | 开发者工具没勾"不校验合法域名" | 详情 → 本地设置 → 勾选它 |
| `连不上` | 后端没起 | 终端跑 `npm start` |
| `后端已连上，但 AI 未配置` | `server/.env` 缺 key | 填 `DEEPSEEK_API_KEY` |
| `超时` | 地址不通 | 真机预览时 `127.0.0.1` 指向**手机自己**，要改成开发机的局域网 IP |

**为什么必须勾"不校验合法域名"**：微信只允许请求**已备案的 https 域名**，
而 `http://127.0.0.1:8787` 两条都不满足。开发阶段用这个开关绕过；
上线时换成 https + 备案域名，并在 MP 后台配好。

连不上时游戏**照常能玩**（本机算命盘 + 模板文案），只是文案不是 AI 写的 ——
结果页底部会说明这次是哪种来源，降级提示也会区分原因
（"没连上解读服务" / "响应太慢" / "域名未放行" / "额度用完"）。

### 启动场景可以临时改（开发期很方便）
`config/index.js` 的 `START_SCENE` 决定启动进哪个场景。现在设的是 **`'account'`**，
所以你编译后直接看到账号页，方便集中打磨它。

想切回正常流程（首页 → 问答 → 结果）就改成 `'home'`。
⚠️ **上线前必须是 `'home'`** —— 否则用户一进来看到的是某个内页，游戏没法玩；
`npm run check` 会在不是 `'home'` 时提醒你。

（账号页做了适配：作为启动页时，顶部的返回键指向首页而不是"无处可去"，
所以不会被困在这一页。）

### 小程序版
导入 `miniprogram/` 目录（它有自己的 `project.config.json`）。
**首次要先跑 `npm run sync`** —— 共享代码（core/data/config/services/utils）是从根目录同步过去的副本。

### 后端（要用 AI 解读才需要）
```bash
cp server/.env.example server/.env
# 编辑 server/.env，填 DEEPSEEK_API_KEY
npm start                      # 起在 http://127.0.0.1:8787
curl http://127.0.0.1:8787/api/health
npm run test:live              # 真实调用一次，打印文案 / 耗时 / token / 成本
```
开发时开发者工具里勾「详情 → 本地设置 → 不校验合法域名」就能连本地后端。
上线要换成 **https + 已备案域名**，并在 MP 后台配置 request 合法域名。

### AI 模型：实测数据（2026-09 实测）
这台 key 的接口**只认 `deepseek-flash` 和 `deepseek-v4-pro`**，`deepseek-v4.1` 会被 400 拒绝。

| 模型 | 一次解读耗时 | 输出 token（其中思考） | 单次成本粗算 |
| --- | --- | --- | --- |
| `deepseek-flash`（**默认**） | **8.7 / 12.2 / 13.6s** | 1500~2200（思考 1000~1750） | ≈ ¥0.025 |
| `deepseek-v4-pro` | **50s**（另有一次被 max_tokens 截断） | 3336（思考 2933） | ≈ ¥0.029 |

两个都是**推理模型**：会先"想"一大段再写正文，所以 ①`max_tokens` 必须给足
（配成 4000，否则 JSON 会被截断）②超时要留余量（客户端 50s / 服务端预算 50s）
③成本比按纯输出估的要高。**文案质量很好**：它真的会引用你的四柱、轴数值和角色意象，
不是套模板。

**默认用 `deepseek-flash`**：实测同一个提示词下，它 4 倍快、更便宜、JSON 更少截断，
文案也照样具体（`tools/probe-model.js` 可以随时重跑这个对比）。
`v4-pro` 要 50 秒一次，几乎顶着超时线，偶尔还会因为思考吃满 max_tokens 被截断。
想换回 pro：`DEEPSEEK_MODEL=deepseek-v4-pro`，同时把几个预算一起放大
（`server/config.js` 里都有注释说明）。

体验上不用担心这十几秒：**本机图谱和匹配结果是秒出的**，结果页先渲染出来，
AI 文案回来了再原地替换，并给一句"深度解读已补上"的提示。超时也只是退回本机模板文案。

## 4. 架构与数据流

```
小游戏（Canvas 自绘）
   │  ① 本机算图谱：星象 + 干支 + 灵数 → 八维向量（几毫秒，秒出）
   │  ② 本机匹配角色：形状匹配 → 主推/副推/反向
   │  ③ 只把「匿名数字」发后端：八轴分数、星座下标、干支下标、色号
   ▼
自建后端 server/（持有 key · 缓存 · 限流 · 违禁词兜底）
   │  ④ 结构化提示词：命盘清单 + 锚点 + 硬约束 → DeepSeek
   │  ⑤ 严格 JSON → 逐字段校验（长度/违禁/编造角色名）
   ▼
  ⑥ 回填到本机模板文案上 → 用户永远能拿到一份完整解读
```

三条关键设计：

1. **API key 只在服务端**。小游戏包体可以被解包，写进前端的 key 等于公开；微信也会拦下直连模型域名。
2. **命盘在本机算，AI 只写文案**。角色由本机算法决定（确定性、可缓存、不会胡说角色），
   AI 只负责把解读写成人话。这比"让 AI 决定一切"稳定、便宜，而且**断网也能出结果**。
3. **同一命盘永远同一份解读**。按「命盘种子 + 角色库版本」缓存 30 天，
   用户不会刷出两套说法，你也不用为同一个命盘付两次钱。

## 5. 小游戏框架怎么用（要加界面时看这里）

Canvas 里没有 DOM，所以自己做了一层最小的**保留模式 UI**：

```
Scene（场景）
 └─ root: Widget 树          常驻内容
 └─ overlay: Widget 树       弹窗/提示，命中优先级更高
     └─ Widget { x, y, w, h } 坐标相对父控件
         ├─ drawSelf(ctx)     只画自己
         ├─ hitTest(x, y)     命中测试（逐层扣掉父坐标）
         ├─ update(dt)        返回 true 表示需要重绘
         └─ onTap / onDrag / onLongPress
```

**加一个新场景**只要三步：
```js
// 1. 写 src/js/scenes/myscene.js
const { Scene } = require('../router.js');
const { Label, Card } = require('../ui/widget.js');
class MyScene extends Scene {
  onEnter() { this.build(); }
  build() {
    this.root.clear();
    this.root.add(new Label({ x: 32, y: 100, w: 686, text: '你好', size: 32 }));
    // 卡片的内容加到 card.content 里，坐标相对卡片内边距
    const card = new Card({ x: 32, y: 200, w: 686 });
    card.add(new Label({ x: 0, y: 0, w: 630, text: '面板里的字' }));
    card.fitHeight(0);
    this.root.add(card);
  }
}
module.exports = MyScene;

// 2. 在 boot.js 的 router.register({...}) 里注册一行
// 3. this.stage.router.push('myscene') 就能跳过去
```

**已封装的控件**（`src/js/ui/`）：
`Widget`（基类）/ `Panel` / `Hotspot` / `Label` / `Paragraph`（自动折行）/ `Tag` /
`ProgressBar` / `Card` / `SectionTitle` / `HLine` |
`Button`（4 种样式 + 按压动画）/ `ScrollView`（含惯性与视口裁剪）/ `Wheel`+`WheelGroup`（滚轮选择器）/
`PickerSheet` / `Toast` / `Modal` / `prompt`（拉起原生键盘）|
`Starfield` / `TopBar` / `TabBar` / `CharCard` / `Dimbars` / `ResonanceRing` / `FateTags`

**性能上的两个刻意设计**：
- **脏标记重绘**：静止页面不重绘（`stage.requestRender()` 才画），文字阅读页不会让手机发烫。
  需要连续动画的场景设 `scene.alwaysRender = true`。
- **视口裁剪**：`ScrollView` 只画视口内的子控件（图鉴 60 张卡只画 4 张）。

## 6. 命盘算法（哪些是真算的）

| 部分 | 实现 | 精度 |
| --- | --- | --- |
| 太阳星座 | 低精度天文公式算太阳视黄经 → 分星座 | ~0.01°，判星座绰绰有余 |
| 月亮星座 | 月亮黄经主项 | ~0.3°，够判星座 |
| 上升星座 | RAMC + 黄赤交角 + 出生地纬度的球面解 | 取决于出生时间与城市准确性 |
| 年/日/时柱 | 立春分界 + JDN 锚点（2000-01-01 = 戊午日）+ 五鼠遁 | 年/日柱精确 |
| 月柱 | **由太阳黄经反推**（十二"节"正好落在黄经 ≡ 15° (mod 30°)） | 不需要农历表；边界误差 ≈ 15 分钟 |
| 生命灵数 | 生日数字约简（保留 11/22/33） | 定义明确 |
| 姓名数理 | 用字编码折算 | 趣味算法，非传统五格剖象，UI 已如实说明 |

已知简化：不处理真太阳时与历史时区变更；23:00 后是否算次日由 `config.DIVINATION.ZI_HOUR_SWITCH_DAY` 控制。

## 6.4 出生地表（三级地区）

`data/cities.js` 是一张三级地区表：**省级 → 市级 → 区/县**。

| 层级 | 内容 | 说明 |
| --- | --- | --- |
| 第一级 | 34 个中国省级行政区 + 海外 | 23 省、5 自治区、**4 直辖市（与省同级）**、**中国香港 / 中国澳门 / 中国台湾** |
| 第二级 | 364 个市 | 每个市都带经纬度，自治州 / 地区不会写成"延边市"（`CITY_SUFFIX` 表） |
| 第三级 | 区 / 县 | 主要城市有真实区县；其余回退成「市辖区」，不用为凑数据堆几千行 |

**为什么第三级不做全**：出生地在这个产品里只有一个用途 —— 估算上升星座。
经度差 1 度 ≈ 4 分钟时差，而上升每 2 小时才走一个星座，所以**市级经纬度已经远超需要**，
第三级只影响选择体验，不参与精度（这就是 `districtsOf()` 有兜底的原因）。

几个必须知道的接口：

| 函数 | 用途 |
| --- | --- |
| `placeOf(o)` | 把任意形态的出生地归一化成 `{ province, city, district, cityLabel }`。**能吃老数据**（只存了 `city:'杭州'` 会反查出浙江省），也能吃空值（回退北京） |
| `placeLabel(o)` | 展示串：`广东省 深圳市 南山区` / `北京市 东城区` / `中国香港 中西区` |
| `locate(province, city)` | 经纬度 + 时区。只传一个参数时按城市名全国搜（兼容老调用） |
| `placeFromRegion([...])` | 小程序版把原生 `<picker mode="region">` 回传的全称（`'广东省'`）还原成短名 |

施工时的两个坑，已经在代码里注释了：

1. **`findCity` 和 `tzOf` 不能互相调用** —— 会绕成死循环（`RangeError: Maximum call stack size exceeded`）。
   两者都走内部的 `wrap()` / 直接查表。
2. **省市同名不等于同一级** —— 北京市的"市"要省掉，但吉林省吉林市是两个层级都得显示。
   判断条件是 `sameAsProvince()`（只对直辖市和特别行政区成立），不是简单的名字相等。

两端的交互不一样，但共用这张表：

| 端 | 三级怎么选 |
| --- | --- |
| 小游戏（Canvas） | 自绘三列联动滚轮（`PickerSheet.link()`）：换省 → 市和区重建并归零，不会留下"广东 成都"这种组合 |
| 小程序版 | 原生 `<picker mode="region">`，再经 `placeFromRegion()` 还原成短名 |


**匹配比的是"形状"不比数值高低**：先把八维向量在它自己的轴上标准化，再比"哪根轴相对突出"。
因为实测命盘的内部标准差只有 8、角色库是 19 —— 直接算距离会让最中庸的几个角色霸榜
（实测一个角色占 41%、60 个角色只有 23 个出得来）。改成形状匹配后：**60/60 角色都能出场，
最高频 7.9%，主推平均共振度 82.4**。三个手感旋钮都在 `config.MATCH`，改完跑 `npm run test:core`
会打印完整分布，并检查有没有角色霸榜或永远出不来。

## 6.5 问答题库（1113 道 · 分层抽样 · 单选与多选）

题库在 `data/questions/`，按轴分文件，`data/questions.js` 只是转发。

| 项目 | 现状 |
| --- | --- |
| 题量 | **1113 道**（9 道手写核心题 + 1104 道扩充题） |
| 覆盖 | 8 根轴各 109~119 道，另有 184 道跨轴综合题 |
| 选项数量 | **2 / 3 / 4 / 5 / 6 个都有**（927 道是 3 选项，二分题 20 道，清单型 5~6 选项 143 道） |
| 多选 | 131 道，形状有「最多 3 项」「1~2 项」「正好 2 项」等 |
| 用户可选题量 | **10 / 20 / 30 / 50**（首页那个「问几道题」选择器，记在 settings 里） |

### 为什么必须分层抽样

题库一千多道，用户只答 10~50 道。抽样是**按轴分层轮转**的（`core/quiz.js` 的 `sampleQuestions`）：

1. 按主轴把题分桶（8 根轴 + 综合题一桶）
2. 每桶单独洗牌，各桶轮转着各取一道
3. 最后整体打乱顺序（不然用户会连答 8 道「光与影」，明显感觉老问同一件事）

**10 道题也必定覆盖到全部 8 根轴** —— 否则用户答完 10 题，图谱可能只动了两根轴，
命盘形状就是假的。这条有测试断言（题量 10/20/30/50 各验一次）。

同一个 `seed + 题量` → 同一套题（重进答题页不会换题）；首页每次「开始匹配」都会换一个
一次性 token，所以同一个用户每次玩到的题也不一样。

### 权重按题量归一（这条最容易写错）

以前固定 9~11 道题、每题 ×1.1。现在能答 50 道，如果还按每题 ×1.1 累加，
单根轴会被推到 ±500，归一化之后**所有命盘都变成"要么全 0 要么全 100"**。

所以每题权重 = `QUIZ_WEIGHT × QUIZ_REF_COUNT / 实际题数`：

> **答 50 道和答 10 道对图谱的总影响力一样，50 道只是更准**（噪声更小）。

实测：全选第一个选项时，10 题的平均偏移 22.0，50 题 22.5。这个断言在 `test:game` 里。

### 多选按平均算

多选题勾 3 个选项，不该等于 3 道题的力度。取所选各项增量的**平均**，
语义上也更顺：勾出来这几条，共同描述了你的一种倾向。

### 加题目 / 改格式

格式说明在 `data/questions/index.js` 顶部，一题就是一个三元组：

```js
['题干', [
  ['选项文案', { light: 12, mercy: 6 }],      // 增量，主轴 ±7~±15，副轴 ±3~±8
  ['另一个选项', { light: -10, order: 8 }, 'fate_breaker']  // 第三个元素是可选的命途 id
], { hint: '第一反应最准', multi: 3 }]        // 备注可选：hint / multi
```

- `multi: 3` = 最多勾 3 项；`multi: [1, 3]` = 至少 1 项最多 3 项
- 想偏离所在文件的主轴，在备注里写 `dim: 'fate'`
- **往文件末尾追加**不会影响已有题的 id（id 是"前缀 + 模块内连续序号"）
- 写完跑 `npm run test:core`：题干长度、选项数量（2~6）、增量范围、轴名、
  命途 id、重复选项、多选上下限，全都会逐题校验

## 7.35 数据边界（**重要，且之前的说法要更正**）

这个项目有三层数据，边界是刻意划的：

| 数据 | 存哪 | 为什么 |
| --- | --- | --- |
| 充值记录、畅玩卡 | **游戏账号**（服务端权威） | 涉及钱，必须跨设备 |
| 游玩记录（主推角色/共振度/图鉴/历史） | **账号 + 本机**（本地为主） | 换设备不丢收集进度 |
| 生辰资料（日期/时间/城市/称呼） | **只有本机** | **与账号无关** |
| 命盘（八轴 / 干支四柱） | **只有本机** | 见下面那条更正 |

### ⚠️ 更正：我此前说"生辰不出手机"，这个说法不准确

**干支四柱可以反推出生时刻。** 四柱 → 年月日时的映射是唯一确定的，枚举就能还原。
实测：用四柱枚举 1940–2015 年，命中 `1996-08-19 07:00` 和 `08:00`（实际是 07:20，
落在同一时辰内）。**所以四柱就是生辰的等价物。**

准确的表述应该是分三句：

| | 情况 |
| --- | --- |
| ✅ | **我们自己的服务端不落库任何生辰相关字段**。`server/playlog.js` 有字段白名单，四柱、八轴、命盘种子、姓名、城市全都会被丢掉（有测试断言） |
| ✅ | **账号里的游玩记录只存结果**：角色 id、共振度、稀有度、时间。推不回生日 |
| ⚠️ | **但发给 AI 的那一次请求里含四柱** —— 四柱是解读的核心素材，AI 靠它写出"丙火日主生在甲寅月"这类内容。这里有个取舍 |

**这个取舍由你决定**，开关是 `config.PRIVACY.SEND_PILLARS_TO_AI`：

- `true`（默认）：解读更准，代价是模型服务能看到可反推生辰的数据
- `false`：只发太阳/月亮/上升 + 八轴数值，不发干支。解读会少一层"日主/四柱"的意象，
  但上行数据就真的只是"数值和星座"了。改一行即可，其它代码不用动

（顺带一提：八轴数值 + 星座**不能**反推出生日期，多对一映射，枚举不出唯一解。
真正能反推的只有干支四柱。）

## 7.45 微信昵称头像（**别照抄老教程**）

账号页顶部和首页顶栏都会显示用户的微信头像。这件事在 2022-10-25 之后变了做法：

> **`wx.getUserInfo` / `wx.getUserProfile` / `open-type="getUserInfo"` 已全部被收回。**
> 现在调它们只会拿到昵称「微信用户」+ 一张灰色默认头像。

所以现在唯一合规的路子是**让用户自己选**：

| 端 | 用的 API | 备注 |
| --- | --- | --- |
| 小游戏 | `wx.createUserInfoButton` | 原生按钮，用户点它才给资料。位置要用 **CSS 像素**，不是设计稿坐标 |
| 小程序 | `<button open-type="chooseAvatar">` + `<input type="nickname">` | 基础库 2.21.2+；给的是**临时路径**，必须 `saveFile` |

小游戏**没有** `chooseAvatar` 的等价物（`wx.createChooseAvatarButton` 这个文档不存在，直接 404）。

### 三个真踩过的坑

**1. 原生按钮是画在 canvas 之上的，它不跟着内容滚动。**
所以它只能放在**固定不动**的位置（我们把头像整行放在滚动区之上）。
放进滚动区的话，用户一滑，按钮留在原地，既压住别的内容又指向错误位置。

**2. 它必须在三种时机被销毁，少一个都会"浮在别的页面上吃点击"：**

| 时机 | 为什么 |
| --- | --- |
| 用户点完 / 超时 | 拿到结果就该收掉；用户一直不点也要有超时（默认 120s） |
| `onExit` | 用户没点就走了 |
| **`onPause`** | 账号页 →（push）→ 图鉴：账号页并没有 exit，按钮会浮在图鉴页右上角 |
| **异步回调里** | 登录态请求 200ms 后才回来，回调里 build 会把**已经离场的页面**重建一遍、又造一个按钮 |

最后一条是测试逼出来的：`AccountScene.isActive()` 就是为了拦住"离场后还响应的异步回调"。
一般规律：**任何异步回调在改页面之前，都要先问一句"我还在台前吗"。**

**3. 头像是异步加载的，组件里不能存图片本身。**
存图片的话，"加载完成"那一刻组件手里的引用还是 null，只有重建页面才换得上。
所以 `AccountBar` / `AvatarRow` 收的是**取值函数** `getAvatar: () => this.avatarImg`，
加载完只需 `requestRender()` 就换上了 —— 和角色立绘一个套路。

### 拿不到怎么办

`services/wechatprofile.js` 会识别**匿名返回**（头像为空、或那张官方灰图）：
判定为"没拿到" → **不写库、不显示**，提示用户，画面上继续用我们自己的徽记。
给用户看一个灰色默认头像，还不如显示我们生成的星芒徽记。

判定**只看头像、不看昵称**：用户完全可以把自己叫「微信用户」，不该因此丢掉他的真头像。

**上线前必做**：在 MP 后台《用户隐私保护指引》里声明「微信昵称、头像」——
没声明的话平台会直接拦掉，表现是"点了按钮什么都没发生"。详见
[docs/COMPLIANCE.md](docs/COMPLIANCE.md) 的「微信昵称头像」一节。

## 7.4 账号与登录（重要：**没有"登录页"**）

微信小游戏的登录是**静默**的：`wx.login()` 拿 code（**无 UI、无需授权**）→ 服务端
`code2session` 换 openid → 完成。**用户进入游戏就已经是登录状态**，不存在输账号密码这一步。

所以账号页回答的是三个问题：**我的账号是什么 / 我玩过什么 / 我的数据存在哪**。
页面上只给标签和值，不做解释性段落（唯一保留的一句是底部的"无需注册"，
因为不说用户会去找登录按钮）。

**账号里存什么**（这才是"游戏账号"的意义）：
- 充值记录、畅玩卡（涉及钱，服务端权威）
- **游玩记录**：累计次数、图鉴、最近 50 局历史 —— 换设备靠它恢复
- 界面上有一张「**你的数据在哪里**」的表，逐项说明什么在账号、什么只在本机

| 展示 | 说明 |
| --- | --- |
| 登录方式 / 账号标识 | 账号标识做了脱敏（`oX8f1c****3kD2`），用户能确认"是同一个账号"就够了 |
| 登录凭证状态 | 有没有 session_key、有没有失效。**它失效会导致支付签名失败** |
| 畅玩卡 | 服务端权威数据，换设备也在 |
| 游玩记录 | 累计次数、已遇见角色、首次游玩时间；可一键从账号恢复 |

**同步策略：本地是主，服务端是备份。** 因为生辰只在本机，本机算出的记录最全；
而且刚玩完的那一局可能还没上报成功。所以合并是**取并集**而不是"服务端覆盖本地"——
图鉴同一角色保留更早的首次时间、更大的次数；历史按 resultId 去重。
上报是**异步且静默失败**的，绝不拖慢用户看到结果。
| **你的数据在哪里** | 生辰/记录/图鉴 = 只存本机；畅玩卡 = 绑定账号 |

页面上明确写了「**微信小游戏不需要注册账号**」——这是有意的，否则用户会以为要注册，
或者四处找"登录按钮"。也声明了「不会获取你的昵称、头像或手机号」（我们确实一个隐私接口都没用）。

### 三个真问题，都已经修掉

**① token 过期会让付费权益"消失"（真 bug）**

原来的 `ownerOf` 在 token 失效时**静默回退到 IP**：owner 从 `openid` 变成 `ip_x.x.x.x`，
查到的权益是空的 —— 用户会看到"我买的畅玩卡突然没了"，而且完全不知道为什么。

现在加了 `resolveOwner`，把三种情况分开：没带 token → 匿名；token 有效 → 正常；
**token 失效 → 明确返回 401 `TOKEN_EXPIRED`**。涉及钱和账号的接口（支付、权益、账号）
一律用严格版，绝不静默降级。客户端 `services/api.js` 收到 401 会**自动重新登录并重试一次**。

**② 平台错误码不能一视同仁**

`code2session` 有两个必须区别对待的错误：
- **40029**（code 无效）：多半是 code 被用过（code 只能用一次），**引导重试**
- **40226**（code blocked）：「**高风险等级用户，小程序登录拦截**」——
  这不是用户能修的，**不能给"重试"的错觉**，话术要得体，而且**不能因此挡住玩游戏**
  （命盘是本机算的，登录只影响 AI 解读和付费）

**③ `checkSession` / `resetSession` 的签名方式不一样**

这两个接口的签名是 **`hmac_sha256(session_key, "")`——对空字符串签名**，
而支付的用户登录态签名是对**请求体原文**签名。混用会直接 87009 无效签名。
所以代码里单独抽了 `emptyBodySignature()`，不复用支付那套。

另外 `resetUserSessionKey` 有三个官方约束必须知道：**重置后原凭证立即失效**、
**重置不能续期**（继承原过期时间）、**不允许频繁重置**。所以它是"补救"手段而不是"续期"手段
（遇到 87007 = 凭证已不存在，只能重新登录），页面上也做了二次确认。

## 7.5 使用额度与付费

### 现在就能用的（不需要版号）
免费 **2 次** → 用完弹解锁面板 → **看一次激励视频换一次** → 可以囤券。
这条链路完整可用，而且**符合纯 IAA 定位**，现在就能提审上线。

额度分层（`services/entitlement.js`），判定顺序就是优先级：
1. **畅玩卡**（付费买的时长）—— 有效期内不限次，**不消耗任何东西**
2. **免费额度**（2 次）—— 一次性
3. **广告解锁券** —— 看一次广告换一次
4. 都没有 → 弹解锁面板

把"卡"放最前面是有意的：用户花了钱还去扣他的免费次数或广告券，是明显的体验 bug，
也是退款投诉的常见来源。

### 付费（`¥6/1天`、`¥30/7天`、`¥100/30天`）

**⚠️ 默认关闭，因为开通虚拟支付有硬门槛**（官方《虚拟支付进件》原文）：
必须企业/个体工商户主体 + 已接入中宣部实名认证系统 + **游戏版号、软著、自审自查报告**。
没有版号就开不了。详见 [docs/RELEASE-CHECKLIST.md](docs/RELEASE-CHECKLIST.md) 第〇节。

代码是完整的，配好就能开：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 配置 | `config.PAY` | 档位（价格单位是**分**）、免费次数、开关 |
| 权益 | `services/entitlement.js` | 三层判定 + 消耗 + **幂等发货**（纯本地，可测） |
| 准入 | `services/gate.js` | 每次占卜前唯一的准入裁判 |
| 支付 | `services/payment.js` | 能力探测 → 后端签名 → 拉起支付 → 确认发货 |
| 面板 | `src/js/ui/unlock.js` | 解锁 UI（付费入口"有则显示"） |
| 服务端 | `server/pay.js` | **签名（AppKey/session_key 只在服务端）** + 发货推送 + 幂等 |

**三个容易做错、已经踩过的点**：
1. **价格单位是「分」**（接口要求 `goodsPrice`），配错会让用户付 100 倍的钱。
   UI 显示时才转成元。
2. **`signData` 必须原样传递**。它是服务端生成好下发的字符串（含空格和换行），
   客户端重新 `JSON.stringify` 一遍签名就对不上了。
3. **支付成功 ≠ 权益到账**。平台的发货消息是**服务端异步推送**的，客户端必须再确认一次；
   确认不到就给"稍后到账"，绝不能当成功。而且推送会重试，**发货必须幂等**
   （测试里连推 6 次验证只发一次）。

**iOS 是有条件支持**：Android/Windows/OHOS 默认支持；iOS 需要 iOS 15+ / 基础库 3.10.3+ /
客户端 8.0.68+，且**不支持沙箱环境**。错误码 `701001` 就是 "ios 禁止支付"。
所以必须先探测再拉起，老 iOS 用户只能走广告。

## 7.6 服务端接口（api.weixin.qq.com）

这些**只能在服务端调**，而且都要 access_token。我们用了 4 个 + 1 个自建推送地址：

| 能力 | 接口 | 文件 |
| --- | --- | --- |
| 登录 | `sns/jscode2session` | `server/wxauth.js` |
| access_token | `cgi-bin/stable_token` | `server/accesstoken.js` |
| **查订单（付没付钱的权威来源）** | `wxa/game/queryorderinfo` | `server/gameapi.js` |
| 文本内容安全（有 UGC 才需要） | `wxa/game/content_spam/msg_sec_check` | `server/gameapi.js` |
| 发货推送 | 自建 `GET/POST /api/pay/notify` | `server/wxnotify.js` |

### 消息推送是这一块最容易配错、错了用户就收不到货的地方

三个必须知道的点（官方协议，和"普通 Webhook"很不一样）：

1. **URL 验证是 GET，不是 POST**。后台填 URL 时微信先发
   `GET ?signature&timestamp&nonce&echostr`，要按
   `sha1(sort([Token, timestamp, nonce]).join(''))` 验签，通过后**原样返回 echostr**（纯文本）。
   **不做这一步，后台会一直显示"未通过"，配置根本存不下来** —— 结果就是用户付了钱，
   发货推送一条都收不到。
2. **需要 Token 与 EncodingAESKey**（都是你自己在后台填的，不是微信发给你的）。
3. **安全模式下消息体是 AES-256-CBC 加密的**：`aeskey = base64decode(EncodingAESKey + '=')`、
   `iv = aeskey[0..16]`、PKCS#7 填充，明文结构是 `random(16) + msgLen(4,大端) + msg + appId`。
   回复微信的内容**不需要**加密。

另外「**必须要开启道具发货推送**才能收到回调请求」——后台里那个开关要记得打开。

### access_token：别用错接口

用 **`stable_token`**，不要用老的 `getAccessToken`（官方原文：「推荐使用此接口替代」）。
普通模式（不传 `force_refresh`）**有效期内重复调用不会刷新 token**，所以可以放心缓存；
平台会提前 5 分钟更新，我们也跟着提前续期。⚠️ **强制刷新模式每天限 20 次**，用错会把线上 token 打废。

⚠️ 服务端接口有 **IP 白名单**：报 `40164` 就是服务器 IP 不在白名单，去 MP 后台加。

### ⚠️ 一处我无法确认、所以做成了可切换的地方

`pay_sig`（查订单用）和 `PayEventSig`（发货推送用）的算法都指向同一份
**《支付请求签名算法说明》**，而它放在**腾讯文档里、需要权限才能打开**，不在微信文档站内。
所以"拼接串里放接口英文名还是 URL 路径"这一条**我无法从公开文档确认**。

能确认的只有 `wx.requestMidasPaymentGameItem` 文档给的例子（用的是**接口英文名**），
所以默认按同一口径实现，并把模式做成配置 `MIDAS_SIG_MODE`。

**接入真实支付时的自查**：查订单返回 **`90011`**（pay_sig 签名错误）→ 换个模式试；
返回 **`90010`** 则是 `signature`（用户登录态签名）错了，那个算法是确定的：
`hmac_sha256(session_key, 请求体原文)`。

### 顺手把"信客户端"升级成了"平台说了算"

`/api/pay/confirm` 现在会调 `pay_v2.queryOrder` 向平台核账：
- 平台说已支付 → 发货（幂等）
- 平台说**未支付** → 返回 `NOT_PAID`，客户端**绝不发权益**（客户端上报的支付成功是可以伪造的）
- 查询不可用（没配 key / 网络问题）→ 退回 `pending`，由发货推送这条权威路径兜底

测试里验证了 `biz_id = 2`（1 = 代币，2 = **道具直购**）—— 这个写错会查不到订单。

## 9.4 小游戏特有的坑（读 API 文档挖出来的）

| 坑 | 后果 | 已做的处理 |
| --- | --- | --- |
| **右上角胶囊按钮会盖住内容** | 只避开刘海不够：实测带刘海设备 `safeTop=88`，胶囊底边在 **160**，顶部标题会 literally 压在胶囊下面 | `device.js` 算出 `contentTop = max(safeTop, capsule.bottom)`，所有贴顶元素改用它；自检场景把胶囊占位用红虚线画出来 |
| **等 AI 时用户锁屏，请求被中断** | 官方明确：进后台 5s 内没结束的请求会 `fail interrupted`。我们的 AI 现在约 9~14 秒（flash），慢的时候更久 | 请求期间 `wx.setKeepScreenOn(true)`，拿到结果立刻恢复 |
| **弱网时白等 50 秒** | 弱网下 AI 大概率超时，用户干等还白花 token | `wx.onNetworkWeakChange` 检测到弱网**直接走本机解读** |
| **冷启动的启动参数不够用** | `getLaunchOptionsSync` 只给冷启动；从分享/二维码**再次进入**时拿不到 | 改用 `wx.getEnterOptionsSync`（同时覆盖冷热启动） |
| **内存告警后自动回收太慢** | 清完缓存内存仍紧张，可能被系统杀 | `level>=10` 时调 `wx.triggerGC()` 主动催 GC |
| **图片缓存不会自动释放** | 占位立绘是离屏画布，最占内存 | 收到内存告警清缓存；接真图后注意 `InnerAudioContext` 要 `destroy()` |
| **版本号不能用字符串比大小** | `'2.29.1' > '2.3.0'` 得到 `false` | `services/update.js` 提供 `compareVersion`；优先用"API 存在判断" |
| **分享 query 有格式要求** | 必须是 `k=v&k=v` | 我们不带 query（避免把生辰放进分享链接） |
| **隐私授权能不能不处理** | 不注册 `onNeedPrivacyAuthorization` 就用平台统一弹窗；我们**没用任何隐私接口**（连剪贴板都没用），所以平台不会弹 | 详见 API-CHECKLIST 第三节，含"以后加什么功能就要回来处理" |

## 9.5 踩坑速查（开发者工具里的报错）

### `module 'src/js/boot.js' is not defined, require args is './src/js/boot.js'`
**代码包里的文件被开发者工具剔掉了**，不是路径写错。原因是这两个开关：

| 文件 | 字段 | 改成 |
| --- | --- | --- |
| `project.private.config.json` | `setting.ignoreDevUnusedFiles` | `false` |
| `project.config.json` | `setting.ignoreUploadUnusedFiles` | `false` |

它们会做静态依赖分析，只把"它认为有人引用"的文件打进代码包。
分析一旦没跟上入口的 require，整个 `src/` 会被判成无引用而排除，运行时自然加载不到。
**`project.private.config.json` 是开发者工具自动生成的**（已 gitignore），
重新导入项目时它可能又带着 `true` 回来 —— `npm run check` 会检查这两项，别忽略它的告警。

另外入口的 require 刻意写成「先赋值、再调用」的独立语句（不写 `require('./x.js').start()`），
这种最朴素的形式静态分析最不容易读错。

### 其它常见噪音（无害，可以忽略）
- `worker path empty` —— 工具的本地文件监听 worker，与代码无关
- 基础库的鸿蒙/HarmonyOS 兼容提示 —— 官方公告

### `[jsbridge] invoke getSystemInfo fail: jsbridge not ready`

打开工具就报这一条，**这是开发者工具自己的启动时序问题，不是你的代码**：

- 整条栈都是 `WAGame.js`（运行时自己的代码），没有我们工程的任何一帧
- 最后一帧停在 `get deviceOrientation` —— 是模拟器为了配置屏幕方向去问宿主，
  而这时桥（jsbridge）的握手还没完成

但它**可能顺带造成一个真实的副作用**：桥没就绪时 `wx.getWindowInfo()` 也会抛，
我们就只能用一个兜底的 375×812 —— 以前这意味着**整场都用错尺寸**（底部被裁掉、
胶囊按钮的位置也算错），而且完全静默。所以现在启动日志会自报屏幕来源：

```
[game] 我推的星运 v0.1.0 启动完成 12ms · 750x1624 设计稿坐标 · dpr=2 · 屏幕 375x812(windowInfo) · 首场景=home
```

| 括号里 | 含义 | 要做什么 |
| --- | --- | --- |
| `windowInfo` | 量到了真实屏幕（走 `wx.getWindowInfo`，2.20.1+） | 那句报错纯属噪音，无视 |
| `systemInfo` | 新 API 没拿到，退回了 `wx.getSystemInfoSync` | 也拿到了真实尺寸，无视 |
| `fallback` | 两个都没拿到，用的是兜底尺寸 | 启动日志会再补一句 warn；boot 自动重试补测（最多 6 次、间隔递增），量到真实尺寸后**从零重建当前场景**重排 |

真机上不会出现这个报错（桥在脚本开始执行前就已就绪）。
相关代码：`src/js/device.js` 的 `SOURCE` / `measured`、`src/js/stage.js` 的 `reapply()`、
`src/js/router.js` 的 `rebuild()`。`npm run test:game` 会模拟"两个 API 都抛"的情况，
验证它不会静默用错尺寸。

### 文字叠在一起 / 内容被裁掉（布局审计）

这类问题靠肉眼一页页看太累，而且改一处很容易碰坏另一处。所以 `test:game` 里有一节
**布局审计**（第 17 节），它把每个页面**真正画出来的文字**逐条拿出来查：

| 检查 | 判据 |
| --- | --- |
| 文字压文字 | 两条文字的墨迹矩形相交超过 3px（墨迹按 ±0.5em 估） |
| 左右越界 | 文字跑出画布左右边界 |
| 跑到画布下方 | 没被任何裁剪区挡住、却画在屏幕外面 |
| 压到胶囊按钮 | 文字进入右上角胶囊区域 |
| 脏文案 | 文字里出现 `undefined` / `NaN` / 未替换的 `{占位符}` |

它会打印每一页的问题清单（哪两句话、相交多少像素、在哪个坐标），
最后一句话断言"所有页面 0 处可疑"，**所以以后改布局再犯会直接测试失败**。

想让这套检查成立，测试的假 canvas 必须做两件真事（都在 `tools/game-test.js` 里）：

1. **真的跟踪变换矩阵** —— 不然记下来的坐标全是局部坐标，回答不了"这两个字在屏幕上
   是不是压在一起"；
2. **真的跟踪裁剪区** —— 滚动容器是 `save → rect → clip → translate(-scrollY)` 画的，
   不算裁剪就会把"已经滚出视口、根本看不见的内容"也算进来，于是和底部导航的文字
   比出几百条假重叠。

> 这个审计第一次跑就抓出两个真 bug：账号页的头像整行被画低了 148px（把绝对坐标
> 喂给了只认本地坐标的 `drawSelf`），以及资料卡的「默认」徽标和出生日期行叠了 5px。

### 手机上打开只有背景 / 白屏（真机 ≠ 开发者工具）

**真实案例（2026-09，基础库 3.17.2，真机日志）**：

```
[log]   [game] 我推的星运 v0.1.0 启动完成 18ms · 750x1630 · dpr=3 · 屏幕 440x956(windowInfo)
[error] [game] draw:o 出错: addColorStop with invalid params
        emblem@game.js ← value@game.js
```

**根因：`draw.emblem` 里用了 `hsla()` 颜色，而微信小游戏的 Canvas 不接受 `hsl()` / `hsla()`。**
开发者工具的 canvas 是浏览器的、支持 hsl，真机是原生实现、直接抛
`addColorStop with invalid params` —— 于是就成了"工具里一切正常、真机某一帧抛异常"。

**为什么表现是"只剩背景"**：Canvas 自绘只要**某一帧抛一次异常**，异常会从 `scene.draw`
冒出去，而 `requestAnimationFrame(frame)` 写在 `frame()` 的最后一行 —— 执行不到，
**帧循环就断了，画面永远停在那一帧**。首页里 Starfield 是第一个子控件（背景画完了），
第二个就是 AccountBar（它画徽记 → 调 emblem → 抛），所以背景之后什么都没了。

> **规矩**：颜色一律用 `#rrggbb` 或 `rgba()`。需要按色相算色的地方用
> `draw.hslToRgba(h, s, l, a)`（`src/js/draw.js`）。
> 测试的 mock canvas 现在**按真机口径拒绝 hsl/hsla**，谁再写就当场失败。

**现在有三道保障**（`src/js/errview.js` 与 `src/js/stage.js`），这类失败不会再隐身：

| 保障 | 作用 |
| --- | --- |
| 每帧的 `update` / `draw` 和场景 `onEnter` 都包了 try-catch | 出错不再断循环，游戏继续跑 |
| 出错就把**错误卡画在屏幕上**（红色描边 + 页面名 + 消息 + 前两行栈 + "把这一屏截图发给开发者"） | 手机上能直接读出原因；同一条错误只累计次数不刷屏；换页自动清掉 |
| `config.DEBUG.VCONSOLE`（默认 true）让**非正式版**自动调 `wx.setEnableDebug` | 手机上出现调试按钮，能看 console 和完整报错；正式版按 `envVersion` 判断，不会开 |

**排查三步**：① 看屏幕上有没有红色错误卡 ② 有点调试按钮的话看 `[game] ... 出错` 的行
③ 都没有 → 失败发生在 `boot.start()` 之前，`game.js` 的兜底画面会接管。

**另外三类"真机才会犯"的错也已修**（都是 `getContext` / 画布假设的问题）：

| 问题 | 后果 | 修法 |
| --- | --- | --- |
| `text.js` 里 `canvas.getContext('2d')` 可能返回 **null**（离屏画布上限/未就绪） | 之后 `ctx.font = ...` 抛 TypeError，而这个调用在场景 `build()` 里 → **整页建不出来** | 校验 ctx 可用，否则退回宽度估算 |
| `assets.js` 生成占位立绘时同样可能拿到 null ctx | 图鉴/角色页崩 | 返回 null，调用方退回纯文字渲染 |
| `game.js` 的兜底画面**又调了一次 `wx.createCanvas()`** | 只有第一次是上屏画布，之后都是离屏的 —— 舞台建好之后才失败的话，**错误画面画到了看不见的地方** | 优先复用 `boot.getStage().canvas`，字号按画布宽度缩放 |

**测试侧同步加严**：mock canvas 现在按真机口径校验
`createLinearGradient` / `createRadialGradient` / `addColorStop` 的参数
（NaN、偏移越界、颜色里含 undefined 都会抛）—— 这类参数在开发者工具里常常被忽略，
在真机上直接抛异常，是"工具正常、真机崩"的典型原因。



### 真机上「账号登录不上」

**先看这一条**：`config.API_BASE` 默认是 `http://127.0.0.1:8787`。
**在真机上 `127.0.0.1` 指向手机自己**，所以永远连不上你开发机上的后端 —— 不是账号坏了。

| 环境 | 能不能连本地后端 |
| --- | --- |
| 开发者工具 | 能（并勾上「不校验合法域名」） |
| **预览（扫码）** | **不能**：127.0.0.1 指向手机，而且未备案域名会被拦 |
| 真机调试 / 体验版 | 换成开发机局域网 IP（`http://192.168.x.x:8787`）后可以；真机调试还能绕开域名校验 |
| 正式版 | 必须是自己备案过的 **HTTPS 域名**，并在 MP 后台「开发设置 → 服务器域名」里加上 |

页面现在会如实区分这两种失败（以前统一显示"登录已过期"，会让人以为账号坏了）：

| 情况 | 页面显示 |
| --- | --- |
| 连不上服务器 | **连不上服务器** + 原因 + 怎么办（提示改成局域网 IP / 用真机调试） |
| 服务端说 token 失效 | 登录已过期 —— 这才是真的过期，点「重新登录」即可 |

游戏本体**离线也能玩**：图谱和匹配都在本机算，只有 AI 文案、账号同步、充值需要后端。

### 页面划不动 / 滑不动

小游戏没有原生滚动，滚动是我们自己在 Canvas 上实现的，所以"划不动"有一类特定原因。
**已修的三类**（`tools/diag-scroll.js` 会回归验证，4 机型 × 4 场景 × 5 种起点）：

| 症状 | 原因 | 修法 |
| --- | --- | --- |
| 从**空白处/胶囊下方**开始滑完全没反应 | 那时 `hitTest` 返回 `null`，找不到滚动容器 | 滚动容器的命中区向外扩展（`hitPadding`），并用坐标再兜一次（`findScrollableAt`） |
| 从**底部导航（TabBar）**上沿开始滑没反应 | 命中的是不可滚动的控件，沿 parent 链找不到容器 | 同上（坐标兜底） |
| **嵌套滚动**时内层到底后整片卡死 | 内层到边界后位移被丢掉 | 到边界时把位移**传给外层容器**（`parentScrollable`） |

### 滚轮选择器（出生日期 / 时辰 / 出生地）划不动
这个和上面的页面滚动是**两套路径**，根因也不同：

| | 页面滚动 | 滚轮选择器 |
| --- | --- | --- |
| 控件 | `ScrollView` | `Wheel` |
| 为什么能/不能命中 | **覆写了 `hitTest`**，直接返回自己 | 用基类 `hitTest`，最后一行是 `return this.tapEnabled ? this : null` |
| 结果 | 正常 | `tapEnabled` 默认 false → **返回 null** → 事件穿透到外层 `PickerSheet` → 输入层找不到滚动目标 |

所以症状很有迷惑性：**页面能滚，但轮盘划不动**。修法做了三层：
1. 基类兜底：`return this.tapEnabled || this.scrollable ? this : null` —— 可滚动的控件本来就该能被命中，
   不该依赖每个控件记得设 `tapEnabled`（这样以后新增滚动控件也不会再犯）
2. `Wheel` 显式声明可命中，并注释说明原因
3. 坐标兜底 `findScrollableByPoint` **改成先查浮层再查主内容** —— 选择器挂在 `overlay` 上，
   只查主内容会漏掉它

**教训**：`tapEnabled = false` 的控件**永远不会成为事件目标**，命中的会是它的外层容器。
任何需要接收点击或拖动的自制控件都必须显式打开它（或者像 `ScrollView` 那样覆写 `hitTest`）。

还有一个副作用已修：**按下按钮后拖动页面，按钮会卡在按压高亮状态** ——
因为拖动接管后原控件收不到 `onPressEnd`，现在无论是否被接管都会补发。

⚠️ 这套修复有个容易做错的细节：命中扩展（`hitPadding`）必须**晚于**真实控件生效。
场景的命中测试跑两轮：先用严格模式（只认真实范围），什么都没命中才用宽松模式。
否则滚动容器会把**它上方**的按钮（筛选 Chip、返回按钮）的点击抢走。

### 联动滚轮（地区选择器）：静态列不能被清空
`PickerSheet.link()` 支持"某列变了就重建它后面的列"。这里有个已经踩过的坑：

建列时**必须给每一列都解析出候选项**，不能只解析第 0 列、把后面的留空等 `syncFrom` 填 ——
`syncFrom` 会跳过静态列（`items` 是数组的列），于是日期选择器的月/日两列就永远是空的，
表现为**选完年月日出来的是 `1999-undef`**。判断规则：
- `items` 是**函数** → 联动列，跟着上游重建并归零
- `items` 是**数组** → 静态列，从头到尾不许动（否则"选了年，月日被重置回 1"）

### 用户手机上是一片黑，但开发者工具里正常
先看 Console 有没有报错。如果连报错都没有，那就是引导早期就挂了 ——
`game.js` 里已经做了兜底：**引导失败会把错误标题和堆栈直接画在画布上**（小游戏没有控制台，
不这么做就真的什么都看不到）。

### 后端连不上（结果页显示"星象信号不好，这次用本机图谱为你解读"）
这是**设计内的降级**，不是 bug。检查：
1. `npm start` 起了吗（默认 `http://127.0.0.1:8787`）
2. 开发者工具 → 详情 → 本地设置 → **勾上"不校验合法域名"**（小游戏同理）
3. `npm run test:live` 能不能通
