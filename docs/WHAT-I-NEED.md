## A. 卡住项（没有它就跑不起来 / 上不了线）

### A1. 小游戏 AppID + 类目决策 ⚠️ 不可逆
- 去 [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册，**注册时选"游戏"类目**。
- ⚠️ 官方原文：「一旦你选择了游戏类目，该类目将不可修改变更为其他小程序类目」——
  也就是说这个账号以后**只能是小游戏**，不能改成工具/娱乐类小程序。
- 我需要你确认：**确定走小游戏吗？**（见文末"三个待决策"第 1 条，这条影响很大）
- 有了 AppID 后替换 `project.config.json` 里的 `touristappid`。

### A2. 后端域名 + 服务器（必须 https + ICP 备案）
- 官方原文：域名「必须经过 ICP 备案」「不能使用 IP 地址或 localhost」「不支持配置父域名，使用子域名」。
- 你需要给我：**一个已备案的 https 域名**（例如 `api.yourdomain.com`）+ 一台能跑 Node 20+ 的机器
  （1 核 2G 起，DeepSeek 调用本身不吃 CPU，主要是网络 IO）。
- 拿到后：改 `config/index.js` 的 `API_BASE`，并在 MP 后台「开发 → 开发设置 → 服务器域名」里加上它。
- 本地开发不需要它：开发者工具勾「不校验合法域名」就能连 `127.0.0.1`。

### A3. DeepSeek API Key + 预算上限 ✅ 已配（待你轮换）
- 你给的 key 已写进 `server/.env`（该文件在 `.gitignore` 里，不会进代码库）。
  ⚠️ **它已经在聊天里明文出现过，上线前请去后台轮换一次。**
- 模型名以接口为准：**只支持 `deepseek-flash` 和 `deepseek-v4-pro`**，
  你说想用的 **`deepseek-v4.1` 会被 400 拒绝**（接口原话：
  `The supported API model names are deepseek-flash, deepseek-v4-pro`）。
  **现在默认用 `deepseek-flash`**（同一个提示词实测对比后选的，见下）。
- **实测数据**（真实调用，见 `npm run test:live` / `tools/probe-model.js`）：

  | 模型 | 耗时 | 输出 token（含思考） | 单次成本粗算 |
  | --- | --- | --- | --- |
  | deepseek-flash（**默认**） | 8.7 / 12.2 / 13.6s | 1500~2200（思考 1000~1750） | ≈ ¥0.025 |
  | deepseek-v4-pro | 50s（另有一次被 max_tokens 截断） | 3336（思考 2933） | ≈ ¥0.029 |

  flash 快 4 倍、更便宜、JSON 更少截断，文案照样具体（会真的引用你的四柱和角色意象，
  不是套模板）；pro 每次 50 秒，几乎顶着超时线，思考还容易吃满 `max_tokens` 把 JSON 截断。
  而且**结果页不受影响**：本机图谱是秒出的，AI 文案回来了再原地替换。
- 需要你定：**每人每天几次**（`DAILY_PER_USER`，现在 10 次）、
  **全站每天上限**（`DAILY_GLOBAL`，现在 3000 次）。按十次/人算，一万个日活约 ¥2900/天 —— 
  所以这两个闸门一定要按预算收紧，别用默认值上线。
- 省钱的两条已就绪：①同一命盘只生成一次（缓存 30 天，实测二次请求 `source=cache` 不花钱）
  ②想快一倍/省一点就把 `DEEPSEEK_MODEL` 换成 `deepseek-flash`。
  请以 [DeepSeek 官网](https://platform.deepseek.com)最新定价为准。

## B. 美术资源（**基本不需要了**）

角色卡现在走「**星徽 + 文字**」方案：徽记按角色 id 稳定生成（同心多边形 + 星芒 + 名字首字，
见 `src/js/draw.js` 的 `emblem`），**一张图都不需要**，全流程就能跑、能看、能上架。

这不只是省事，还顺带解决了两件事：
- **版权**：引用作品的角色，用官方立绘有实实在在的风险；自己画又有成本。徽记是我们自己生成的几何图形。
- **包体**：主包只有 334KB（上限 4M），不用担心 60 张图塞不下、也不用配分包。

**所以立绘从"必须项"降级成了"可选项"。** 下面的 B1/B2 只在你想加强视觉时才需要做。

### B1.（可选）角色立绘
想加就加：把图按 `src/assets/chars/<角色id>.png` 放好，把 `config/index.js` 的
`ENABLE_ART` 改成 `true`，卡片顶部的徽记区会换成图片。命名表仍然有效：

- 比例 3:4，建议 750×1000，单张压到 150KB 以内
- 格式只能用 **png / jpg**（⚠️ webp 不在小游戏的文件白名单里，上传会失败）
- 优先级：先画传说（17 张），再史诗

### B2.（可选）启动封面
750×1334，png/jpg。不提供就用微信默认封面。

### B3.（可选）图标
分享按钮、返回、设置这类地方目前用**文字和几何图形**表示。
官方设计指南建议分享按钮用「符号化图形 Icon」（给用户平台统一认知），
所以如果要做，优先做这几个：

| 图标 | 用在哪 | 规格 |
| --- | --- | --- |
| 分享 | 结果页 / 角色页 | 88×88 @3x，PNG 透明底 |
| 返回 | 各页顶栏 | 同上 |
| 图鉴 / 我的 | 底部导航 | 同上 |
| 未解锁 | 图鉴剪影 | 同上 |

### B4.（可选）音频
| 资源 | 用途 |
| --- | --- |
| `tap.mp3` | 按钮点击 |
| `reveal.mp3` | 结果揭晓 |
| `collect.mp3` | 新角色入图鉴 |
| `bgm.mp3` | 背景音乐（记得做"可关闭"，否则容易被投诉） |

格式支持 mp3/wav/m4a/aac/ogg ✓。**没音频也完全不影响**，缺文件就静默不播。
⚠️ 接的时候注意：`InnerAudioContext` **不会自动释放**，不用时要 `destroy()`，否则内存泄漏。

## D. 我需要你确认的三个决策

### 1. 品牌名要不要改？（建议：改）
现在叫**「我推的星运」**，`占星` 落在官方明确点名的「星座运势」敏感区间里（原文见 `docs/COMPLIANCE.md`）。
我在 `config/copy.js` 里已经准备了安全备选：**「我推的角色」/「命途镜像」/「角色命途」/「谁是你」**。
改名的成本是**一行**（`BRAND.NAME`），但目录名、备案主体名、MP 后台名称要你自己跟着改。

### 2. 走小游戏还是小程序？（建议：先小游戏，小程序留着做后手）
两个工程现在**都在这个仓库里、都能跑、共享同一套算法和后端**：
- 根目录 = **小游戏**（Canvas 自绘，能放激励视频广告、能进游戏中心）
- `miniprogram/` = **小程序版**（WXML 写的，文字阅读体验更好，代码类目可自选）

我强烈建议**保留小程序版**：小游戏的"游戏类目不可逆"，如果审核卡住，你至少还有一个能提审的形态。
代价只是一条 `npm run sync` 命令（改共享代码后同步一次，测试会检查是否同步过）。

### 3. 角色库规模（60 个够吗）
现在是 60 个角色、8 部作品混搭。三个方向你挑：
- **保持混搭**（现在）：覆盖面广，但每个用户抽到的概率发散
- **聚焦单作品**（比如全是某部动漫）：粉丝向、传播强，但**版权风险显著上升**
- **换原创角色**：零版权风险，但你得自己想 60 个角色的设定和立绘（工作量最大，最安全）
