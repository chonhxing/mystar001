# 发布流程与硬性要求清单

从官方文档（[接入指南](https://developers.weixin.qq.com/minigame/introduction/guide/)）逐页读出来的，
按**你实际要操作的顺序**排。带 ⚠️ 的是"漏了会卡住或被打回"的。

**总时长：IAA 游戏（靠广告变现，就是我们）预计 13~37 个工作日。**

---

## ⚠️ 零、如果要做付费，流程会变（先读这段）

**当前状态：代码里付费功能是完整的，但默认关闭。** 因为开通虚拟支付有两个硬门槛：

### 开通条件（官方《虚拟支付进件》原文）
> - 主体类型为**个体工商户或企业**已认证小游戏
> - **已接入中宣部实名认证系统**
> - **版号，软著自审自查报告及相关授权**

**没有游戏版号（ISBN）就开不了虚拟支付。** 版号申请周期通常数月到一年。

### 开通后发布流程的变化（IAA → IAP）

| | IAA（只靠广告，现在） | IAP（含付费） |
| --- | --- | --- |
| 备案情况 | 【情况二】约 10~30 工作日 | 【情况一】约 **5~12** 工作日（更快） |
| 审核时效 | 13~37 工作日 | 9~22 工作日 |
| 资质审核 | IAA 版 | **IAP 版**（另有一套材料） |
| 中宣部实名系统 | 平台已统一协助接入，**无需开发者操作** | **必须自己接**：企业注册 → 添加游戏（需批文号、ISBN）→ 渠道绑定（91440300708461136T 深圳市腾讯计算机系统有限公司，勾选"实名认证"和"数据上报"）→ 同步游戏名/版号/bizid 到 MP 后台 |
| 分账/提现 | 无 | 要签协议、设提现账户与管理员、扫码完成签约（约 2 个工作日） |

### iOS 的支付是"有条件支持"（官方原文）
`wx.checkIsSupportMidasPayment`（基础库 3.10.3+）：
> Android、Windows、OHOS 平台：默认支持虚拟支付
> iOS 平台：需满足以下环境要求才可能支持 —— iPhone/iPad、**iOS 15 及以上**、
> 基础库 3.10.3 及以上、客户端 8.0.68 及以上；苹果支付**不支持沙箱环境**
> 若该 API 都不存在，则 **iOS 一定不支持**虚拟支付

错误码 `701001` 就是 "ios 禁止支付"。所以**必须先探测再拉起支付**，不能假设能用。
老 iOS 用户只能走广告那条路 —— 这是平台限制，不是我们的 bug。

### 开通后必须做的配置（漏一项用户就收不到货）

1. MP 后台「虚拟支付2.0 - 基本配置 - 基础配置」里配 **发货推送**：
   - **URL**：`https://你的域名/api/pay/notify`（必须 http/https，80/443 端口，**3 秒内要响应**）
   - **Token**：自己起一个复杂串 → 填到 `server/.env` 的 `WX_NOTIFY_TOKEN`
   - **EncodingAESKey**：点随机生成 → 填到 `WX_ENCODING_AES_KEY`
   - 加解密方式选**安全模式**（推荐）
   - ⚠️ 保存时微信会发 **GET 请求验证**（要原样返回 `echostr`）。**这一步不过，配置存不下来**，
     点后台的"模拟推送"可以测。
2. **打开「道具发货推送」开关**（官方：「必须要开启道具发货推送才能收到回调请求」）
3. MP 后台「道具配置」里把三个档位建好，**id 和价格必须与 `server/.env` 完全一致**
   （价格单位是分；不一致会报 `-15016`）
4. MP 后台「开发管理-开发设置-**IP 白名单**」加上服务器出口 IP（不加会报 `40164`）
5. 填 `MIDAS_APP_KEY` / `MIDAS_OFFER_ID` / `MIDAS_ZONE_ID`

### 所以现在的策略
**先按 IAA 上线**（免费 2 次 + 看广告解锁，链路完整、可过审），
等版号下来把 `server/.env` 里的 MIDAS 配置填上、`config.PAY.ENABLED` 改 `true`，
付费入口就会自动出现（不用改代码、不用发版逻辑）。

## 〇、先确认我们的定位

| 项 | 我们的情况 | 影响 |
| --- | --- | --- |
| 变现方式 | **IAA**（广告），没有内购 | 走 IAA 流程；备案选【情况二】 |
| 虚拟支付 | 不开通 | **中宣部实名认证无需自己接**，平台已统一协助接入 ✓ |
| 主体 | 待定 | 企业主体必须先做微信认证才能提交备案 |
| 二级类目 | 待选（建议「休闲」） | ⚠️ **与实际游戏内容不符会在提审时被驳回** |

> **IAA vs IAP**：IAA = 广告变现（我们），IAP = 内购。两者的备案流程、审核时效、资质要求都不同。
> 我们选了 IAA 就**不要开通虚拟支付**，否则要自己去中宣部实名认证系统做企业注册、添加游戏、
> 渠道绑定、同步信息到平台，多出一整套流程。

### ⚠️ 提审前必须解决："广告位没配 = 免费无限"

**现状**：`config.ADS.ENABLED = false` 且广告位 ID 为空。而代码里为了不让流程卡死，
默认策略是**拿不到广告实例时直接发放一次解锁**
（`services/reward.js` 的 `unlockByAd()`，唯一的策略出处）。

**后果**：提交材料写的是 IAA（广告变现），但线上**一个广告都不播、也不收钱**，
用户用完 2 次免费后点一下"看广告解锁"就能无限继续 —— **描述与实际不符**，
审核员还会点到一个"没播广告却直接给奖励"的按钮。

**二选一，没决定之前不要提交审核**：

| 选择 | 要做的事 |
| --- | --- |
| 做广告变现 | MP 后台开通流量主（需满足平台的流量主要求）→ 创建激励视频广告位 → 把 ID 填进 `config.ADS.UNITS.divinate_again` → 打开 `config.ADS.ENABLED` |
| 暂不做广告 | 把 `config.ADS.GRANT_WHEN_UNAVAILABLE` 改成 `false`（**一个开关**：没广告就明确提示"广告位暂未开放"，不发放奖励），同时把简介里的变现描述去掉 |

⚠️ 以前解锁面板和充值页各写了一份"没配就白送"，改一处会漏另一处；
现在收敛进 `services/reward.js` 的 `unlockByAd()`，上面的开关对两处同时生效。

### ✅ 虚拟支付的"已购权益丢失"已经补上了（2026-09-17）

**曾经的缺口**：`services/payment.js` 的 `syncFromServer()`（换设备/重装后从服务端
把付费权益找回来）定义了但没有任何地方调用。服务端接口和存储都是好的，只是客户端不拉。

后果：用户买了 30 天畅玩卡 → 换手机 → 本地权益没了，服务端有记录却没人去取 →
投诉、退款，且会被认定"付费后未提供对应服务"。

**现在已经接上两处**（改代码时别把这两处删掉）：

| 时机 | 位置 |
| --- | --- |
| 启动时（异步、不阻塞首屏） | `src/js/boot.js` 的 `restoreEntitlement()` |
| 进"开通畅玩卡"页时 | `src/js/scenes/recharge.js` 的 `restorePass()` |

两处最终都走 `payment.syncFromServer()`（内部已判断 `PAY.ENABLED`，
没开付费时不发请求）。详见 `docs/SYSTEMS.md` 第 14 节。

## 一、并行阶段（这几件事可以同时做）

### 1. 注册账号 ⚠️ 不可逆
- 入口：[mp.weixin.qq.com](https://mp.weixin.qq.com) → 前往注册
- ⚠️ **注册时必须选「游戏」类目**。官方原文：
  「一级类目，不支持修改，且小游戏账号只有"游戏"这个类目（注册时勾选），无法更换或删除，**如选择错误只能重新注册**」
- 个人主体**不支持**文化互动、角色类、牌类三种二级类目

### 2. 名称 / 简称 / 头像
- 办结时限：正常直接生效；命中名称保护词 1~3 工作日；名称占用投诉 7 工作日 + 7 天保护期
- ⚠️ **游戏名不能与已获批的游戏重名**（备案会被驳回），且**名称要与游戏内容有关联性**
  —— 官方举例：「不能用《三国群英》来命名与三国题材无关的消除类游戏」
- 名称规范见《小程序名称、简称设置规范》和《小游戏特别规范-2.1 游戏名称》
- 建议：名字里体现"角色/命途/性格匹配"的意象，别用与内容无关的炫酷词

### 3. 类目设置
- 二级类目在**发布前都可以改**（文化互动类目除外），发布后不可修改
- ⚠️ 「如二级游戏类目与实际游戏内容不符，将会在提审版本时驳回」
- 我们建议：**休闲**（我们的核心循环是答题+收集，不是动作/角色扮演）

### 4. 微信认证
- 办结时限 **1~3 个工作日**
- ⚠️ **企业主体必须先完成微信认证，才能提交小程序备案**

### 5. 适龄提示设置 ⚠️ 最容易漏、且直接影响备案
- 入口：MP → 设置 → 基础设置 → 基本信息 → 适龄提示
- 依据：《未成年人网络保护条例》《未成年人保护法》《防止未成年人沉迷网络游戏的通知》
  《网络游戏适龄提示》团体标准
- 设置后**需提交平台审核**，通过后平台统一在启动页《健康游戏忠告》右侧展示（不遮挡游戏内容）
- 分档：**8+ / 12+ / 16+**

**我们的建议：12+**。对照标准：

| 分档 | 关键判据 | 我们 |
| --- | --- | --- |
| 8+ | 画面简约卡通、无复杂故事背景与人物关系、无陌生人社交 | 我们引用的是动漫/游戏角色，有既定的作品背景 → 不完全满足 |
| **12+** | 画面为卡通/动漫风格（无写实）、**可存在清晰完整的适量故事背景和人物关系**、**可存在部分基于历史和现实事件的改编但不会与现实混淆**、社交系统若有需依法管理 | ✅ 我们引用的是动漫角色、无写实画面、无陌生人社交 |
| 16+ | 3D 写实风格、丰富宏大的背景设定、大型团队任务、竞技对抗为主要玩法 | 不符合 |

- ⚠️ 官方明确列了「**适龄提示未设置或者未通过**」是导致**备案被驳回/影响时效**的常见原因之一
- 即使游戏内自己加了适龄提示，**仍然必须**在 MP 后台设置，并保持两处一致

### 6. 资质审核
- IAA 与 IAP 要求不同（我们是 IAA）
- 文化互动类目必须**先完成资质审核才能提交版本审核**；其他类目可并行

## 三、备案（最耗时，务必尽早提交）

**两个备案，顺序不能颠倒：先【小游戏备案】→ 再【小程序备案】。**

### 3.1 小游戏备案（前置审批）
- 路径：账号设置 → 小程序备案 → 去完善 → 小游戏备案 → 前往提交
- 时限：**平台初审 1~2 工作日 + 主管部门 10~20 工作日**
- 提交要求：
  - 清晰、完整、真实介绍游戏内容（场景、玩法、功能）
  - **上传对应截图，截图需保持尺寸、版本一致**
- ⚠️ 提交后处于"审核中/已通过"状态时**不允许修改游戏名称或账号主体**；
  必须先等【小程序备案】完成后才能改
- ⚠️ 审批要求「游戏名称、账号主体在任何阶段都保持与当前提审游戏名称、提审账号主体一致」，
  不一致会直接驳回
- ⚠️ 常见驳回原因里就有**适龄提示未设置或未通过**
- Q：已经拿到版号的游戏怎么办？→ 有《网络游戏出版物号核发单》的游戏**暂无需**提交小游戏备案
  （走"情况一"）。我们没有版号，走"情况二"

### 3.2 小程序备案
- IAP 选【情况一】（约 5~12 工作日）；**IAA 选【情况二】（约 10~30 工作日）** ← 我们
- ⚠️ **管局审核通过后下发备案号，才算完成备案，才能发布版本**

### 3.3 备案后的维护
- 完成备案后如果改了名称/主体，要**同步更新备案信息**，否则可能出现限制搜索、限制新增用户
- 长时间不一致会影响正常运营

## 四、隐私合规（必做，且我们现状很好）

官方《小游戏隐私合规开发指南》的要求：

**步骤一：自查是否处理用户个人信息**
**步骤二：配置隐私政策**（MP → 设置 → 服务内容声明 → 用户隐私保护指引）
- 如果**完全没处理**任何个人信息 → 勾选「确认承诺未处理用户任何信息」，无需后续流程
- 如果**有处理** → 需配置隐私政策 + C 端授权交互 + 上报授权结果

**我们的情况**（这是优势，别破坏它）：

| 数据 | 去向 | 是否算"处理个人信息" |
| --- | --- | --- |
| 姓名 / 出生日期 / 出生时间 / 出生地 | **只存用户手机本地**（wx.setStorageSync） | ⚠️ 属于个人信息，**需要如实披露**（收集/存储发生在用户设备上，而你是服务提供者） |
| 八轴分数 / 星座下标 / 干支下标 | 开启 AI 解读时上传到我们后端（匿名化） | 匿名化后可视为非个人信息 |
| 分享链接 | **不含任何命盘数据** | ✅ 干净 |

- 官方标准 API 清单里，我们**一个都没用**（没取昵称头像、没定位、没相册、没麦克风、没传感器、
  没微信朋友关系）—— 这是很干净的起点
- 填写建议：「收集：出生日期/时间；用途：本机算法计算；是否上传：否；是否共享：否」

**⚠️ 内容安全（运营规范 5.18）—— 有一条直接点名了我们这类产品：**

> 5.18.2 **昵称测试/算命类UGC小程序**，小程序内可任意输入敏感违规内容，无安全过滤的。

含义：**如果用户能自由输入文字并展示/上传，就必须调用内容安全检测接口**（`msgSecCheck`）。
- 我们现在让用户输入「称呼」，但它**只存本地、从不上传、也不展示给别人** → 目前不需要接
- ⚠️ 一旦以后加了「用户写一句话让 AI 解读」「命盘昵称公开展示」这类功能，**必须**接入内容安全校验

## 六、性能要求（官方给了硬数据，直接影响留存）

| 指标 | 官方数据 | 对我们的含义 |
| --- | --- | --- |
| 首屏打开留存率 | **约 75~80%**（四分之一的人在看到首屏前就流失了） | 第一屏必须快 |
| 启动时长 → 流失 | **缩短到 4 秒内可减少约 30~40% 流失** | 我们的启动要压进 4 秒 |
| 内存异常退出占比 | 约 2%（重度游戏 5~8%） | 注意图片缓存 |

**我们目前的有利条件**：
- 主包只有 **334KB**（上限 4M），下载快
- 启动**不联网**（命盘本机算），没有网络等待
- 占位立绘是代码生成，不占包体

**已做的措施**：
- 启动耗时已埋点（`analytics.info('boot', ...)`），会打进日志
- 脏标记渲染：静止页面不重绘（省电、降发热）
- 视口裁剪：图鉴 60 张卡只画可见的
- 收到内存告警时清占位图缓存

**待做的**：立绘接入后要测启动与内存（那时候包体会从 334KB 涨到几 MB）。

## 六点五、版本更新机制（会影响"改了合规措辞多久生效"）

官方原文要点：

- **静默更新**：发布新版本后**无法立刻影响所有用户**，最差情况下要在发布后 **24 小时**内
  才会把新版本信息下发到用户；用户下次打开时先更新再打开
- **启动时更新**：冷启动会检查更新，但只是**异步下载**新包，**新版本要等下一次冷启动才生效**
- **强制更新**：用 `wx.getUpdateManager`（`onCheckForUpdate` / `onUpdateReady` /
  `onUpdateFailed` + `applyUpdate`）
- ⚠️ 官方原话：「**如果对于版本依赖高的游戏，建议始终开启检测更新 API**」
- ⚠️ 已知问题：Mac 客户端和低版本 PC 客户端在特定场景下 `onCheckForUpdate` 回调**不会触发**，
  不要过度依赖这个回调（`onUpdateReady` 才关键）

**为什么这对我们特别重要**：
1. 我们会改**合规措辞**（敏感词替换）—— 旧版本用户还看着旧文案和旧品牌名
2. 我们会加/改**角色** —— 旧版本的图鉴进度和结果会对不上
3. 后端接口契约如果变了，旧版本可能直接不可用

**已实现**（`services/update.js`，已接进 `boot.js`）：
- 启动时挂 `getUpdateManager`，新版本下载完成后用 **`wx.showModal` 原生弹窗**问用户是否重启
  （用原生弹窗而不是自绘弹窗：原生弹窗永远在最上层，而且**即使 Canvas 渲染挂了也弹得出来**）
- 更新下载失败也会提示用户（重启会重新下载），不静默吞掉
- 顺带提供了 `compareVersion` / `supports(minVersion)`：官方明确说**不能用字符串比版本号**
  （`'2.29.1' > '2.3.0'` 会得到 false），并且 <= 2.20.1 的基础库要用 `getSystemInfoSync` 拿版本号

**另外两个可用的手段**：
- MP 后台「设置 → 基本设置 → **小程序最低可用版本**」：设成最新版，强制用户用新版本
- **灰度发布**：MP → 管理 → 版本管理，可按**发布比例**或**白名单灰度**（微信号，上限 100 人）
  ⚠️ **灰度版无法取消发布，请谨慎使用**

## 六点六、低版本兼容

- 判断方式有两种：**API 存在判断**（推荐，简单可靠）或**版本号比较**
- 我们代码里用的都是 API 存在判断，例如：
  `wx.getWindowInfo ? wx.getWindowInfo() : wx.getSystemInfoSync()` —— 这正好是官方推荐写法 ✅
- 可以在 MP 后台查看近 30 天用户的基础库版本占比，再决定"最低基础库版本设置"
- 设了之后，低于该版本的用户**无法打开**小程序，会提示升级客户端

## 七、设计规范里能直接落地的几条

读《小游戏设计指南》摘出来的、我们**已经对上或该对上**的：

### 分享（3.5 / 3.6）
- **分享点宜少宜精**，每次游戏过程**不宜超过 1 个** ✅ 我们只在结果页放了一个
- 用户更愿意分享的题材：知识分享、炫耀性、**个人创作**、**反差冲突**、**物品收集进度**
  → 我们的「你的命途图谱」正好是"个人创作 + 反差冲突"，图鉴进度是"物品收集"，命中三条
- 分享按钮要用**符号化图形 Icon**（平台统一认知）→ 我们目前是文字按钮，**待替换成图标**
- 关闭按钮要及时出现、清晰可见 ⚠️ 我们的分享用的是系统 `wx.shareAppMessage`，这个由平台控制 ✓
- 分享卡片要与点进来后的体验呼应，避免秒退
  → ⚠️ 我们分享链接**不带命盘数据**（隐私考虑），新用户进来看到的是首页而非同一个结果。
  这是有意的取舍，但官方明确提到"前后不一致会导致秒退"。**建议以后做"分享图"承载结果**，
  用图片表达而不是靠参数传数据。

### 留存（4.1~4.4）
- 设置单次/每日/每周/长期目标 ✅ 我们有每日提示（日）+ 图鉴收集（长期）
- **长期收集目标要在游戏主界面有所体现** ✅ 首页有「已遇见 N / 60」
- 成就系统 / 道具系统 → 待做
- 配置游戏圈、游戏客服收集反馈 → 待做

### 变现（5.3）
- 激励视频最适合的场景：「**再获得一次游戏机会**」—— 文档原话是
  「与'再来一次'相比，游戏玩家可能更乐意，参与度很高」
  ✅ 我们的「看一次广告 · 换个角色」正是这个模式
- 也可以做：提高过关奖励、给提示/帮助、替代游戏内货币

### 体验红线（运营规范 2.9 / 2.10）
- ⚠️ **2.9.1 分享卡片的文案、图片与游戏内容无关** → 封禁分享能力 3~30 天直至永久
  ✅ 我们的分享文案就是角色名 + 共振度，与内容强相关
- ⚠️ **2.10.1** 首屏必须能正常"开始游戏"，不可直接弹第三方跳转；**不允许任何形式的误触**
- ⚠️ **2.10.2** 广告不可遮挡"开始/继续游戏"按钮，不可欺骗/误导点击
  ✅ 我们的广告是用户主动点击才播放
- ⚠️ **2.10.3** 发布状态的小游戏必须可正常体验 → **后端挂了游戏也必须能玩**
  ✅ 我们做了本机降级，AI 不可用时照样出结果
- ⚠️ **5.1.1 强制分享**：分享后才能解锁/查阅/下载 属于违规
  ✅ 分享按钮不给任何奖励

## 八、时间线估算

```
第 1 天    注册账号 + 设置名称/头像 + 选类目
第 1-3 天  微信认证（1~3 工作日）
第 1 天    适龄提示设置并提交审核
第 1-2 天  提交版本审核（1 自然日）  ← 可与备案并行
第 1-2 天  小游戏备案 平台初审
第 3-22 天 小游戏备案 主管部门审核（10~20 工作日）
第 12-42 天 小程序备案 情况二（10~30 工作日）
────────────────────────────────
合计约 13~37 个工作日（多个环节可并行）
```

**关键路径是备案，不是审核。** 版本审核只有 1 天，备案要几十个工作日。
所以**尽早开始备案流程**，代码开发完全可以并行做（官方也明确说了"游戏开发与上面流程均可同时进行"）。
