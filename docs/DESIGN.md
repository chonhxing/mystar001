# 视觉规范（设计令牌与组件规格）

> 这份文档是"界面为什么长这样"的**唯一出处**。改界面之前先看它，
> 改完如果规则变了，回来改这里 —— 否则下一个人（或下一轮的我）
> 会按自己的审美重新发明一套，页面又开始"层级不清、细节粗糙"。

## 一、四条基础规则

界面丑从来不是"不够花哨"，而是**层级不清 + 留白松散 + 细节不统一**。
对应的四条规则，全部落在 `src/js/theme.js` 的令牌上：

### 1. 文字四级，不许乱用

| 令牌 | 亮度 | 用途 |
|---|---|---|
| `COLOR.ink` (90%) | 最亮 | 大标题、卡片标题、关键数值 |
| `COLOR.ink2` (66%) | 次亮 | **正文最低用这一档**，再暗就不合格 |
| `COLOR.ink3` (47%) | 辅助 | 标签、说明、表单标签 |
| `COLOR.ink4` (34%) | 极弱 | 只给脚注/合规/装饰编号，**不要拿它排正文** |

写代码时优先用语义别名 `TXT.body` / `TXT.sub` / `TXT.aux` / `TXT.faint`，
这样"正文太暗"这类调整只改一处。**已经踩过的坑**：正文大量用 ink4，
整页灰蒙蒙看不清（用户原话："现在很多地方 45% 太暗"）。

字号走 `FONT`（设计稿 750 宽，值 = 逻辑 px × 2）：

```
hero 68 / h1 52 / h2 40 / h3 32 / body 28 / small 24 / tiny 21 / micro 19
big 64（共振度那种整页锚点）  cardTitle 34  qtitle 48
```

⚠️ **字号必须是整数**。真机 Canvas 对 `font` 简写的解析比开发者工具严格，
`700 116.55px sans-serif` 这种带小数的字号可能被**静默忽略**（不报错、
字体保持上一次的值），表现是"该显示的字没显示"。统一走 `theme.font()`。

### 2. 卡片一套规格

`CARD = { radius: 32, pad: 32, gap: 24, fill: 'rgba(255,255,255,0.04)', stroke: 'rgba(255,255,255,0.08)' }`

- 圆角统一 32（= 逻辑 16px）。以前有 20/28/36 三种，是"细节粗糙"的主要来源。
- 内边距统一 32。**卡片子控件的宽度必须写成 `contentW - CARD.pad * 2`**，
  不要写死 `- 56` 这种数：内边距一改，写死的那些就会溢出一截（布局审计会抓到）。
- 卡片间距统一 `CARD.gap` = 24。

### 3. 金色只用在三处

**主按钮 / 选中态 / 关键数字。** 其余地方（分割线、标签条、小节标题文字）不用金色。

满屏金字会让金色贬值 —— "哪儿都是金，就等于哪儿都不金"。
小节标题因此是「金色竖条 + **白色**文字」：保留一个金色锚点，但不滥用。
（有测试断言钉住这一条：`SectionTitle` 的文字必须是 `COLOR.ink`。）

### 4. 主次必须拉得开

同一个页面里，**一个主按钮 + 若干次级**：

- 主按钮：`variant: 'primary'`（金色竖直渐变 + 顶部 1px 高光 + 整行宽）
- 次级：`variant: 'ghost'`（金描边）
- 更次：`variant: 'plain'`（白描边）
- **纯文字出路**：`variant: 'text'`（"以后再说""跳过这题"这种次级出口）
- 添加类：`variant: 'dashed'`（虚线描边，"这里还能再放一个"）

以前"以后再说"和"看广告"都是药丸按钮，用户以为它们平级、分不清主次。

## 二、动效规范

| 位置 | 规则 | 实现 |
|---|---|---|
| 场景入场 | 内容整体上移 20px + 淡入，0.3s 缓出 | `Scene.enterT` / `EASE.outCubic` |
| 按压反馈 | 缩到 0.97，0.15s | `Widget.pressScale`（控件只要翻 `pressed`） |
| 数字出现 | 从 0 滚到目标值 | `NumberTicker`（默认 900ms） |
| 进度条 | 宽度过渡 + 一道流光 | `ProgressBar` / `draw.flowBar` |
| 主按钮引导 | 呼吸微光（0.9→1） | `Button({ pulse: true })` |
| 加载态 | 六边形描边旋转 + 中心星点闪烁 | `draw.hexRing` + `draw.sparkle`（占卜页） |
| 背景 | 星座连线（10~12% 透明）+ 每 8~15 秒一颗流星 | `draw.constellation` / `draw.meteor`（Starfield 内） |

⚠️ **动画不能让"看到的"和"点得到的"不一致。**

- 场景入场那 0.3s 里，控件的命中坐标**不跟着动画走**（动画只画在 draw 里），
  所以动画期间点按钮也不会点空。
- 解锁面板的下滑动画（`SLIDE = 72`）同理：位移只画在 `drawSelf` 里，
  而且**一碰就落位**（`hitTest` 里 `settleAnim()`）——
  面板里最后一个按钮贴着屏幕底部，如果让整体 y 跟着动画走，
  动画期间它的命中区会被推到屏幕外，用户按"看得见的位置"点会点空。
- 布局审计（`game-test` §17）审的是**静止态**：它先调 `scene.settle()`
  把所有动画推到终点再量坐标。控件的自入场动画要覆写 `settle()`。

## 三、稀有度用边框光效区分（图鉴的核心爽点）

`RARITY_STYLE` + `draw.rarityEdge`，强度按稀有度分档：

| 稀有度 | 光效强度 |
|---|---|
| 传说 legend | 1.0（金色微光） |
| 史诗 epic | 0.75（紫） |
| 稀有 rare | 0.5（蓝紫） |
| 寻常 common | 0.3（几乎不发光） |
| **未遇见** | 0.22 + 整卡 50% 透明 + ✦ 星形占位 |

未遇见的卡不发光、半透明、头像位是虚线圆里的 ✦（不是问号 ——
问号读起来像"你答错了"，而空位应该是"等着你去遇见"）。

## 四、图标

`src/js/ui/icon.js`，纯线条矢量（无图片资源），名字 → 直方图。
统一规格：`size` 是外接方框边长，线宽 = size 的 8%，透明度默认 0.6
（"退后一档"是列表图标的规范动作）。

现有：`book clock ticket gear user doc trash shield info calendar check cross
plus edit female male diamond dots card spark`

⚠️ 图标名拼错**不会报错，只是不画**。所以测试里有一条断言：
控件树里所有 `w.icon` 都必须能在 `iconMod.has()` 里找到。

## 五、改界面的检查清单

1. 跑了 `npm test` 吗？其中 **§17 布局审计**是硬门槛：所有页面
   **零**文字重叠 / 越界 / 压胶囊 / 空卡片 / 脏文案。
2. 新加的文字有没有可能和别处重叠？审计会算，但**明显的拥挤先自己看**：
   中文字形按 ±0.5em 估墨迹范围，相邻两行至少留 8px 缝。
3. 右对齐的内容在页面顶部时注意**右上角胶囊按钮**（`stage.contentRight`）：
   文字只要 `right > contentRight` 且 `top < capsule.bottom` 就算"压胶囊"。
   图鉴那个 `40 / 60` 计数器就是因此整体下移了 20px。
4. 卡片子控件的宽度是不是 `contentW - CARD.pad * 2`？
5. 字号是不是整数（走 `theme.font()`）？
6. 新增的动画有没有加 `settle()`？有没有影响命中测试？
